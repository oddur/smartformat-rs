# smartformat-rs

[![CI](https://github.com/oddur/smartformat-rs/actions/workflows/ci.yml/badge.svg)](https://github.com/oddur/smartformat-rs/actions/workflows/ci.yml)

A Rust port of [SmartFormat.NET](https://github.com/axuno/SmartFormat): string
templating with named placeholders, pluralization, conditional formatting, and
list formatting.

The point of this port is that templates written for the .NET library render
**byte-identically** here. That claim is tested, not asserted: the suite runs
2,700+ golden cases whose expected outputs are generated by the real
SmartFormat.NET 3.6.1 in an in-repo harness, across 35 cultures whose formatting
data is likewise read out of .NET itself. Where the two sides genuinely cannot
agree, the divergence is documented in [DESIGN.md](https://github.com/oddur/smartformat-rs/blob/main/DESIGN.md) with a test
pinning each side's behavior. [Why byte-identical output is the goal](https://github.com/oddur/smartformat-rs/blob/main/docs/explanation/byte-compatibility.md)
explains what that costs and where it stops.

```rust
use smartformat::value::ToSmartValue as _;
use smartformat::{SmartFormatter, ToSmartValue};

#[derive(ToSmartValue)]
#[allow(non_snake_case)]
struct Cart {
    Name: String,
    Count: i64,
    Gender: String,
}

let cart = Cart { Name: "Alice".into(), Count: 3, Gender: "f".into() };
let smart = SmartFormatter::default();

let out = smart.format(
    "{Name} has {Count} {Count:plural:item|items} in {Gender:choose(m|f):his|her} cart",
    &cart.to_smart_value(),
).unwrap();
assert_eq!(out, "Alice has 3 items in her cart");
```

## What works today

| Area | Status |
|---|---|
| Parser | Full SmartFormat syntax: nesting, escaping, alignment, selectors (`.`, `?.`, `[n]`), formatter names and options |
| Format specifiers | All .NET *standard* numeric (`B C D E F G N P R X`) and date/time specifiers. Custom patterns like `#,##0.00` are a deliberate hard error so gaps are loud instead of silently wrong |
| Formatters | `list`, `plural`, `cond`, `ismatch`, `isnull`, `choose`, `substr`, plus the default formatter, registered in .NET's order. `time`, `L` (localization) and `t` (template) are available but opt-in, as in .NET |
| Sources | Map keys, list indexes, `?.` null propagation, string members (`Length`, `ToUpper`, …), the `{Index}` selector inside list formats. Persistent and shared variable groups are opt-in, as in .NET |
| Cultures | 35 cultures (en, de, fr, es, pt, ru, pl, ja, ko, zh-Hans, ar, is, …) with number formats, month/day names, and genitive forms taken from .NET |
| Plural rules | SmartFormat's own language table, ported exactly. SmartFormat.NET does not consult CLDR at runtime, so neither do we |
| Error handling | All four .NET `ErrorAction` modes, including byte-identical `FormattingException` messages under `OutputErrorInResult` |

Out of scope: resx parsing, reflection-based sources, and the XML/JSON source
extensions. `LocalizationFormatter` takes a provider trait in place of resx, so
translations come from wherever you keep them.

## Template syntax in one minute

| Template | Args | Output |
|---|---|---|
| `{Name} is {Age}` | `{Name: "Ann", Age: 5}` | `Ann is 5` |
| `{0} and {1}` | `["a", "b"]` | `a and b` |
| `{Person.Address.City}` | nested maps | `Paris` |
| `{City?.Length}` | `City = null` | `` (empty, no error) |
| `{0,10}` / `{0,-10}` | `"x"` | right/left aligned in 10 |
| `{0:N2}` | `1234.5` | `1,234.50` |
| `{0:plural:one\|many}` | `3` | `many` |
| `{0:choose(a\|b):Ay\|Bee\|other}` | `"b"` | `Bee` |
| `{0:cond:>=10?big\|small}` | `12` | `big` |
| `{0:list:{}\|, \|, and }` | `["a","b","c"]` | `a, b, and c` |
| `{0:substr(0,3)}` | `"Alice"` | `Ali` |
| `{0:ismatch(^\\d+$):number\|not}` | `"42"` | `number` |
| `{0:isnull:missing\|{}}` | `null` | `missing` |
| `{0:time:}` (opt-in) | `2h 3m as TimeSpan` | `2 hours 3 minutes` |
| `{:L(fr):Hello}` (opt-in) | provider has `fr` entry | `Bonjour` |
| `{:t:greeting}` (opt-in) | registered template | rendered template |

Escaping uses `\`, as SmartFormat does by default: `\{`, `\}`, `\n`, `\\`,
`\u0041`. The `string.Format`-compatible mode (`{{` escaping) is available
through `SmartSettings`.

The full grammar is in [template syntax](https://github.com/oddur/smartformat-rs/blob/main/docs/reference/template-syntax.md);
every formatter, option and error message is in [formatters](https://github.com/oddur/smartformat-rs/blob/main/docs/reference/formatters.md).

## Cultures

`format` uses the invariant culture. Pass a culture for localized output:

```rust
use smartformat::{SmartFormatter, Value};

let smart = SmartFormatter::default();
let n = Value::List(vec![Value::Float(1234.5)]);

assert_eq!(smart.format_with_culture_name("{0:N2}", &n, "de-DE").unwrap(), "1.234,50");
assert_eq!(smart.format_with_culture_name("{0:C2}", &n, "en-US").unwrap(), "$1,234.50");

let files = Value::List(vec![Value::Int(3)]);
assert_eq!(
    smart.format_with_culture_name("{0} {0:plural:файл|файла|файлов}", &files, "ru")
        .unwrap(),
    "3 файла"
);
```

The culture data is not mapped from CLDR. A dotnet tool in `tools/culturegen`
reads `NumberFormatInfo` and `DateTimeFormatInfo` out of .NET for a fixed
culture list and emits them as Rust source, so a listed culture formats the way
.NET formats by construction. A culture outside the list is an error, never a
guess. [Cultures](https://github.com/oddur/smartformat-rs/blob/main/docs/reference/cultures.md)
lists all 35; [add a culture](https://github.com/oddur/smartformat-rs/blob/main/docs/how-to/add-a-culture.md)
covers shipping one more.

## Feeding values in

Rust has no reflection, so `{Customer.Name}` resolves against a `Value` tree
instead of an object graph. Three ways to build one:

- `#[derive(ToSmartValue)]` on structs with named fields (the example above).
  Field names are used verbatim, so name them as your templates spell them.
- `From` impls for primitives, `String`, `Vec`, maps, `Option`, and
  `jiff::civil::DateTime`.
- Build `Value::Map` / `Value::List` by hand for dynamic data.

## Cargo features

`derive`, `plural`, `time` and `regex-formatters`, all on by default. `time`
implies `plural`. What each one gates is in
[settings and features](https://github.com/oddur/smartformat-rs/blob/main/docs/reference/settings-and-features.md#cargo-features).

## How compatibility is verified

`tools/goldens` is a C# console app that renders every test case with the real
SmartFormat.NET 3.6.1 and writes the results to `goldens/m1.json`. The Rust
suite replays all of them and requires byte equality. Cases the port
deliberately does not reproduce sit in an explicit skip list, each with its
reason, and [DESIGN.md](https://github.com/oddur/smartformat-rs/blob/main/DESIGN.md) keeps the ledger of known divergences with
the test that pins each one.

[How compatibility is verified](https://github.com/oddur/smartformat-rs/blob/main/docs/explanation/how-compatibility-is-verified.md)
describes what the harness pins and what the method cannot prove. The big
divergences to know about are custom .NET patterns (rejected, not imitated), the
UTF-8 against UTF-16 boundary, and the regex dialect `ismatch` runs on.

## Status

Milestones M1 (parser, engine, specifiers), M2 (plural/choose/conditional and
culture data), M3 (list/substr/isnull/ismatch/template), and M4 (TimeFormatter,
LocalizationFormatter, persistent and shared variables) are done. The crate is
not on crates.io yet; the API may still move.
